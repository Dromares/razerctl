# razerctl: standing agent rules

Claude Code loads this file in every checkout. These rules come from the board and CEO; a brief that contradicts one is wrong, so say so rather than follow it.

- **Rust only.** No Python or other scripting language in the tree, tooling and mockups included. Why: a Python icon generator reached `main` because the rule lived only in briefs. `tests/no_python.rs` enforces it (DAN-1396, DAN-1479); the icon generator is `examples/gen_icons`.
- **Merge gate: local-ci and hosted CI, both at the head SHA.** (1) A `scripts/local-ci.sh` PASS from a **non-author**, run in a clean worktree at the PR head SHA, with the log path cited. (2) The hosted `ci.yml` check runs at that head are green: `get_check_runs` (or `actions-list`), newest run per gate, each `completed` + `success` at minute scale. A run of 2 s or less with a 404 log is billing-dead and counts as no evidence. (3) A PR that touches `.github/workflows/release.yml` also shows one green hosted `workflow_dispatch` run of it at the head with `dry_run: true` (the default), citing run URL, conclusion and duration, plus the read-back that it published nothing: `GET /repos/Dromares/razerctl/releases` lists no new release or draft and `git ls-remote --tags origin` shows no new tag. Why: `local-ci.sh` never runs `release.yml`, so the `target/` redirect bug in it (DAN-1693) passed the author's dry run and verification and surfaced on the first hosted run; hosted Actions runs for real now (DAN-1735). To confirm a merge landed, use `git merge-base --is-ancestor <sha> origin/main` plus `git ls-remote origin main`. `verify_closed.sh` is a Hatate script and does not apply here (DAN-1484).
- **A regression test must fail on the parent commit.** Run it there and report that you did. Never loosen an assertion to reach green; fix the code, or say which test is stale and why. Why: a test that passes without the fix proves nothing.
- **Live session safety.** Never `pkill kwin`, and never inject input into the board's live session without an explicit board go-ahead (DAN-1461). Hide hidraw and `/dev/input` from screenshot and e2e runs so the real mouse is never touched. Why: those runs drive the board's actual desktop and device.
- **Design-fidelity pass.** Required for any PR that touches GUI or icon assets (`src/bin/razerctl-gui*`, the icon generator, `assets/`) **and** implements a signed-off mockup: a read-only pass by Oderisi before approval. Not needed for bug fixes, refactors, CLI or protocol changes, packaging, or copy-only changes. Why: the signed-off mockup is the spec, and only the design seat checks the pixels against it (CEO decision, DAN-1482).
- **GUI self-check before design review.** A PR that touches GUI assets (same paths as the design-fidelity pass) **and** implements a signed-off mockup gets the mockup's own checklist run by its author, at the **minimum supported window size** (`min_inner_size`, 780x560 today) and in **every error state** the mockup draws, before the author asks Oderisi for the pass. The author posts a per-item pass/fail in the PR comment, and the design pass is not requested while any item is unchecked. Any dialog with a size criterion gets a fit test, written before review, in the shape of `every_update_dialog_fits_a_780_by_560_window`; any drawn error state gets a test in the shape of `a_failed_update_puts_an_error_line_in_the_status_bar`. Why: PR #26 went to design review with no render at 780x560 and no check of the error status bar, Oderisi's first pass failed items 5 and 6 (DAN-1680), a second verify and design round followed, and both tests were written only after the review (DAN-1736).
- **Post-merge teardown is part of every merge.** Delete the remote branch, `git worktree remove` the ticket's worktrees, and `cargo clean` any you keep. Why: nobody else knows which branches and worktrees are finished, so they pile up.
